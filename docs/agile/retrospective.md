# Sprint 1 Retrospective – Smart Cafeteria Ordering System

## What Went Well
- The team successfully defined the core problem: long cafeteria queues affecting students and staff.
- Initial features such as user registration and basic order placement were implemented.
- Communication was consistent through WhatsApp daily check-ins.
- The GitHub Project Board was actively updated, and tasks were clearly tracked.
- Frontend and backend integration started early, reducing future integration risk.

## What Could Be Improved
- Time estimation for backend tasks (e.g., order processing logic) was inaccurate and caused delays.
- Some tasks were too large and not broken down properly, making tracking difficult.
- Delays in reviewing pull requests slowed down progress.
- Uneven workload distribution among team members in the first half of the sprint.

## Action Items
- Break down complex features (e.g., ordering system) into smaller tasks such as “add item to cart”, “submit order”, etc.
- Improve time estimation by discussing task complexity as a team before assigning.
- Set a rule that pull requests must be reviewed within 24 hours.
- Distribute tasks more evenly across all team members.
- Introduce a mid-sprint check-in to identify risks early.
